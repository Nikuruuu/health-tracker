# Data Model (Neon + Drizzle)

Auth tables (`user`, `session`, `account`, `verification`) are generated by the Better Auth CLI into `src/db/schema/auth.ts`. Don't hand-edit. App tables live in `src/db/schema/app.ts`.

## Conventions
- Every app table: `userId text not null references user(id) on delete cascade`, plus an index on `(userId, date)` where relevant.
- One-per-day tables use a unique `(userId, date)` and upsert on conflict.
- `timestamptz` for instants, `date` for calendar days. User timezone is stored on `profile`.
- Runtime uses pooled `DATABASE_URL` with the Neon serverless driver (`neon-http` for one-shot queries; WebSocket/pooled driver only when a real transaction is needed). Migrations use `DATABASE_URL_UNPOOLED`.
- Workflow: change schema → `drizzle-kit generate` → review SQL → migrate a dev branch first. Never edit applied migrations. Seed script runs on non-production branches only.

## Tables
```
profile        userId PK, units, theme, timezone, heightCm?, startWeightKg, finalGoalWeightKg,
               activePhaseId, maintenanceMode, onboardedAt
targets        userId PK, kcalDeficit, kcalMaintenance, proteinMinG, proteinMaxG, fatPct,
               waterMl, stepsMin, stepsMax
phases         id, userId, name, mode, startDate, endDate?, startWeightKg, goalWeightKg
weightEntries  userId, date, weightKg, note?                  unique (userId, date)
meals          id, userId, date, slot, foodName, source, servings, kcal, proteinG, carbsG, fatG
customFoods    id, userId, name, per100g…, servingG?
waterEntries   id, userId, date, ml
stepEntries    userId, date, steps                            unique (userId, date)
workoutPlan    userId, weekday, sessionType
workouts       id, userId, date, type, durationMin, intensity, kcal, source('plan'|'manual'), completed
measurements   userId, date, waistCm?, hipCm?, chestCm?       unique (userId, date)
photos         id, userId, date, storageKey, thumbKey?, note?
```

## Env vars (`.env.example`, validated in `src/lib/env.ts`)
`DATABASE_URL`, `DATABASE_URL_UNPOOLED`, `BETTER_AUTH_SECRET` (≥32 chars), `BETTER_AUTH_URL`, `NEXT_PUBLIC_APP_URL`, `GOOGLE_CLIENT_ID/SECRET` (optional), `RESEND_API_KEY`, `EMAIL_FROM`, `BLOB_READ_WRITE_TOKEN`, `USDA_API_KEY` (optional). Use separate Neon branches for dev, preview, production, and test.
